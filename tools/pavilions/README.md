# Pavilions Vendor Creator

Version: v1.2

## Purpose

Pavilions Vendor Creator is a structured vendor-list generator for Drupal publishing. It turns pavilion or country-pavilion vendor rows into simple booth-card HTML that can be pasted into Drupal source.

It is not a CRM, vendor database, full CMS, project-management system, approval workflow, or analytics tool.

## Intended Users

The tool is for SEMICON Taiwan website editors who receive vendor lists in Excel-like formats and need to prepare Drupal-safe HTML without hand-editing every card.

## Supported Workflow

1. Create the initial vendor list from pasted rows or sample data.
2. Review parsed vendors before copying.
3. Copy the generated HTML into Drupal source.
4. Save a work file for future updates.
5. Later, load the work file, add/edit/reorder/remove vendors, then copy the updated HTML.
6. If the work file is missing, use limited Restore HTML as a recovery helper for HTML generated by this tool.

## Initial Vendor-List Creation

Use standard format for rows like:

```text
中文名 / English name / Pavilion name / Booth number / Website
```

Use country format for rows like:

```text
No. / Company Name / Contact Person / E-mail / Phone / Address / Website
```

For country pavilions, fill the shared booth field when the source data does not include a booth per vendor.

## Adding Vendors Later

Load the saved work file first. Add a single vendor with `新增單筆`, then fill company name, booth, and URL in the review table. Existing order stays unchanged unless you use the reorder buttons.

## Canonical Working State

After the first parse, the review table is the canonical working list. Edits, added rows, deleted rows, and reordering are saved from that parsed list, not reconstructed from the raw Excel text.

If the raw Excel text is changed after parsed rows already exist, the tool warns before replacing the edited list. Canceling keeps the current review-table list and regenerates from it. Confirming reparses the raw text and replaces the current parsed list.

## Editing Existing Vendors

Edit company name, booth, or URL directly in the review table. Updating one vendor regenerates preview and output from the normalized working list without reparsing unrelated rows.

## Reordering Vendors

Use the up/down buttons in the review table. The tool preserves the current order in preview, copied HTML, autosave, and exported work files.

## Removing Vendors

Use the delete button in the review table. Deletion asks for confirmation and removes only the selected row.

## Missing URL Behavior

Missing URLs do not become `#`. A vendor with a name and booth but no URL remains in the working list and output. It is shown as `Needs check` and renders as a non-clickable card in generated HTML.

## Duplicate Warning Behavior

The tool warns about likely duplicates by comparing normalized vendor names and URLs. It does not merge, delete, or block duplicate rows because similarly named companies or bilingual entries may be legitimate.

## Accepted URL Formats

Accepted URLs:

- `https://example.com`
- `http://example.com`
- Drupal relative paths beginning with `/`, such as `/zh/exhibitor/example`

The tool trims leading/trailing whitespace and normalizes common source formats such as `www.example.com` to `https://www.example.com`. It does not rewrite arbitrary invalid text into a valid-looking URL.

## Restore, Import, And Autosave

- Autosave uses browser `localStorage` and restores the latest same-browser draft on reopen.
- `Save work file` exports JSON with pavilion settings and parsed vendors.
- `Load work file` asks for confirmation before replacing current work.
- Loading samples also asks for confirmation if current work exists.
- `Restore HTML` is a limited recovery helper for HTML generated by this tool. It tries to recover vendor name, booth, URL, and order. It reports failure when no valid cards are found and partial success when entries are skipped.

Use work files as the primary continuity method. Restore HTML is only a fallback.

## Drupal Copy-And-Paste Steps

1. Generate or refresh the output.
2. Check the readiness badge and review table.
3. Resolve `Fix` items before publishing.
4. Review `Check` items, especially missing/invalid URL and duplicate warnings.
5. Switch to preview and confirm order and visual layout.
6. Return to code view and copy HTML.
7. Paste into Drupal source.
8. Save a new work file after Drupal is updated.

## Known Drupal Limitations

- Drupal may strip scripts; this tool does not require scripts in generated output.
- Output uses inline styles for Drupal tolerance.
- Missing or invalid URLs render as non-clickable cards.
- Actual Drupal paste behavior still requires Drupal backend QA before marking publish-ready.

## QA Checklist

- Create a new list.
- Add, edit, reorder, and delete vendors.
- Confirm missing URL cards are non-clickable.
- Confirm invalid URLs are warned and non-clickable.
- Confirm duplicate names and duplicate URLs show warnings.
- Test Chinese, English, special characters, and long names.
- Save and reload a work file.
- Restore generated HTML when needed.
- Compare preview and copied output.
- Check 1, 10, 30, and 60 vendor lists.
- Paste into Drupal test content before production use.

## Known Limitations

- Restore HTML only supports this tool's generated card structure.
- It does not restore intro text, bullets, color, or language from arbitrary Drupal content.
- It does not manage multiple projects in the browser.
- It does not validate whether a URL is reachable.
- Tailwind is still loaded from CDN for the tool UI; generated Drupal HTML does not depend on Tailwind.

## Recovery Steps If Import Fails

1. Try the last saved work file first.
2. If no work file exists, paste previously generated HTML into `Restore HTML`.
3. If restore reports partial success, review skipped entries manually against Drupal.
4. If restore fails, recreate the list from the original Excel source.
5. Export a new work file after recovery.
